# PRP-02B.3 — migration and isolation foundation
Run python -m core.persistence.migrations from repository root with DATABASE_URL pointing to a dedicated migration connection. The runner locks migrations transactionally, checks SHA-256 history and applies the existing schema as 001, then numbered SQL files. Existing untracked databases require inspection before adoption; CREATE IF NOT EXISTS is not schema validation. Never edit applied migration files.
003 enables forced RLS for user_context, memories, goals, projects, approval_ledger and approval_events. Transaction-local app.owner_id is set by trusted application code. It is not a defense against arbitrary SQL execution by the runtime role, which can set this variable. Provision a fresh non-owner runtime login, no inherited privileges, and apply runtime_grants.sql separately. No credentials in Git. Superusers bypass RLS. Child planning tables and events remain outside this policy; runtime grants intentionally omit them. Payload protection and audit mutation triggers do not protect against privileged DDL or forged inserts. Ledger transition constraints, bootstrap wiring, durable tool identity and complete tenant isolation remain open.
Existing integration tests use disposable databases and direct schema setup; they must be adapted to run migrations and exercise a non-owner role before release. No database migration or tests executed in this change.
