# Secure approval resume
The composed agent creates a pending gateway request for a single approval-required action, returns its ID, and does not execute the handler. Mixed or multi-action approval batches fail closed. GET /v1/governance/requests/{id} exposes the stored action to its authenticated owner. POST /decision records human decision; POST /resume has no action payload and reconstructs the stored action without calling the planner. Gateway rechecks ownership, current permission, tool ID and level, arguments and approval validity, then consumes approval before attempting execution. No automatic retry after failure. Concurrent consumption is process-local only.

Limitations: no durable execution receipt, distributed transaction, restart recovery, provider idempotency, or frontend approval UI. A failed or ambiguous external attempt requires reconciliation, not automatic retry. Default registry is empty. Legacy standalone agent executors are not a secure external execution boundary. API bearer credentials identify the single owner, not proof of human presence. Do not expose external writes until durable storage, trusted tool registration and deployment security are validated. Tests added but CI must be verified.
