# Durable governance ledger foundation
Migration 002 adds an owner-scoped approval ledger and event history. Apply after database/schema.sql. The repository stores a JSON snapshot, denies critical approval in single-owner mode, transitions pending to approved/rejected, and atomically claims approved unexpired requests via conditional UPDATE RETURNING. Claim commits before returning. The approval UUID is a local attempt identity, not a provider idempotency guarantee. Failed or unknown outcomes are uncertain; executing and uncertain records are listed for manual reconciliation and never automatically retried.

This is a standalone persistence adapter, not yet wired to the composed gateway or API. A trusted service must bind owner identity, recheck current permissions and tool identity, then call the provider only after a committed claim. No external execution is enabled by this change. Database-level immutability/append-only privileges, migration orchestration, durable tool identifiers, decision reasons, reconciliation endpoint, provider-specific idempotency and receipt redaction are remaining work. Do not store credentials in payloads or receipts. No claim of exactly-once external effects. Integration test requires disposable TEST_DATABASE_URL and has not been executed. No production deployment.
